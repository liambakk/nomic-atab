## Useful for the first look

- What does each file, table or type of record represent?
- What do the important IDs, statuses and quantities mean, including units, currencies and timezones?
- Which IDs connect records across files?
- What does each timestamp refer to?
- Are these current snapshots, historical events or both? Can earlier changes be recovered?
- What happens in other systems or messages that might help explain the records?
- Which docs or rules are worth reading alongside the data?

Flag anything unclear or missing. A few pointers are enough to get started.

## Useful once we narrow down a workflow

For the relevant actions, we may need to understand:

- What information each action needs and who can perform it.
- What could cause it to be rejected.
- Which records change and what happens automatically.
- What happens if it is repeated, cancelled or corrected.
- Which business rules or approvals matter.
- Where people review or override automation.
- Whether a platform or process change affects the examples being reviewed.

For example, if confirming an order reserves stock, explaining both changes helps Liam model the action correctly. Ben or the team can talk through these details when we know which work to focus on.
